## Content-free release manifest

After the candidate commit and installer are fixed, generate a staged manifest from a clean repository:

```powershell
npm run release:manifest -- --source-commit a9ab136d43de9777dbf970c3b6ddef091baebb90
```

The tool reads the synchronized version from the recorded source commit, requires the exact versioned NSIS filename, calculates the file size and SHA-256 digest, checks Authenticode through PowerShell, and records the current evidence commit. It refuses a dirty repository, an unexpected signature state, a mismatched filename, and output paths outside the repository. Its default output is ignored under `tmp/`; it does not upload or publish anything.

Only after disposable-profile acceptance and immutable hosting are complete may the same tool receive both `--download-url` and `--publication-date`. Those fields must be supplied together, and the URL must use HTTPS on the canonical SiteDatum domain or GitLab. Their presence changes the manifest state from `staged` to `publication-candidate`; it does not itself authorize or perform publication.
