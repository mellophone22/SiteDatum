# Information Architecture

## Global navigation
Home, Attention, Projects, and Search/Command. All Projects is an explicit cross-project context rather than an implicit absence of context.

## Project workspace
The selected project identity, phase, and status remain visible in the shell. Its workspace contains Home, Tasks, RFIs, Submittals, Files, Project Controls, Notes, Contacts, and Activity. In All Projects context, the same registers remain reachable as clearly labeled cross-project views.

For a selected project, its phase prioritizes the order of the six project-module navigation links. This is ordering only: every module remains visible and usable. All Projects and custom phases use the stable default order.

Dense registers use a shared non-modal detail-panel pattern: the list remains mounted and full width while closed, opens alongside the list at supported desktop widths, stacks at narrow widths, and returns keyboard focus to the originating control when closed.

## System
Settings and Recovery are separated from daily navigation. Recovery remains available without competing with the normal project workflow.

About SiteDatum sits in system navigation. It presents product identity, statement, creator credit, and the current software version without changing the active project. Search also finds About by product name or "version".

## Attention
Grouped by usefulness: Overdue, Today, Follow-up/Waiting, Upcoming, RFI/Submittal queues.

## Projects
Dense searchable/sortable list with number, name, phase/status, next attention item, open count, recency, pin/archive.

## Project Controls
Project Controls keeps every operational register in one workspace and groups them by working purpose: Coordination (Meeting Minutes, Transmittals), Commercial (Procurement, Change Events), Schedule / Field (Milestones, Daily Reports, Punch List), and Startup & Commissioning (Startup Checks, Commissioning Checks, Commissioning Issues). Calendar, Project Templates, and Reports remain peer views rather than register categories.

## Detail behavior
Prefer drawers/side panels for quick inspection when they preserve context; use full pages for complex work. Avoid long editing in cramped modals.
