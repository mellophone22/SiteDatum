## Design Specificity Verdict

**Product-specific semantics, category-generic composition.** The vocabulary and data model feel authored for a Project Engineer: Waiting, RFI response queues, submittal dispositions, drawing revisions, and explicit Register/Copy/Move operations are credible. Structurally, however, the product remains a generic CRUD/admin shell with nine flat destinations and repeated filter-table-editor compositions. Attention and the selected project should become the organizing spine.

The deterministic detector found two `side-tab` warnings in `src/App.css`: line 27 is a false positive because the accent denotes semantic status; line 32 is a valid finding on the generic white project-overview panel.

No reliable browser overlay was available because the exposed browser surface did not support mutable script injection or console access. The independent design assessment did inspect the built UI at 1280×720.

## Overall Impression

The app is credible, restrained Windows productivity software with unusually good domain terminology. Its biggest opportunity is to stop presenting every register as an equal destination and instead make “what needs attention in this project” the primary mental model.

## What’s Working

1. Domain-specific working concepts are visible instead of generic dashboard metrics.
2. Segoe UI, neutral surfaces, modest radii, separators, and dense tables fit the product and avoid decorative dashboard tropes.
3. Ctrl+K/Ctrl+N, remembered state, inline status, direct selection, and detail panels support repeat use.

## Priority Issues

1. **[P1] Notes form is visibly broken.** Labels, select, and textarea collide because the form lacks the stacking/grid structure used elsewhere. Fix the layout and verify it at 100% and 200% zoom. Suggested command: `$impeccable layout`.
2. **[P1] Navigation does not express the product mental model.** Nine peer header buttons lack persistent active state and selected-project context. Make Attention and Projects primary, with project registers organized within a selected workspace; add `aria-current`. Suggested command: `$impeccable shape`.
3. **[P1] File Move lacks appropriate reassurance.** Copy/Move retain “Register file” labeling and show no source-to-destination consequence preview. Make the heading, button, confirmation, and exact path preview operation-specific. Suggested command: `$impeccable clarify`.
4. **[P2] Capture workflows expose too much too early.** Task, file, RFI, and submittal capture present 7–13 decisions at once. Use progressive disclosure and separate quick capture from lifecycle metadata. Suggested command: `$impeccable distill`.
5. **[P2] Split registers create unnecessary horizontal scrolling.** A 700px table minimum is placed inside a narrower grid column, and an empty detail column remains visible. Make the list full-width until a record is selected, then switch to the split view. Suggested command: `$impeccable layout`.

## Persona Red Flags

**Alex — Power User:** Major lists lack arrow/Enter navigation, sortable headers, and batch actions. Always-expanded task/file forms slow repeat capture.

**Sam — Accessibility-Dependent:** Search lacks a focus trap, focus restoration, and visible Close control; selected rows use color alone; navigation lacks `aria-current`; status announcements are inconsistent; the Notes collision worsens at 200% zoom.

**Jordan — First-Timer:** The Projects empty state points to Settings without a direct action; “Notes & Contacts” becomes “Project context”; file-operation consequences are unclear; nine unmarked destinations weaken orientation.

## Cognitive Load

High: five of eight checklist items fail. Single focus, chunking, one-thing-at-a-time, minimal choices, and progressive disclosure need work. The global header has nine choices; task creation has seven to nine fields; file creation has nine fields plus file selection; RFI and submittal editors expose roughly twelve to thirteen fields.

## Emotional Journey

Opening on Projects feels administrative instead of reassuring. Attention is the emotional peak because it creates control. The Notes collision, long forms, and ambiguous Move action are trust valleys. Success messages provide closure, but next-step guidance and undo are weak.

## Minor Observations

- Eyebrows often repeat headings without adding meaning.
- Activity timestamps should be localized.
- Success messages persist and cannot be dismissed.
- Backup is grouped with project-root validation despite being a separate maintenance task.
- The project overview uses a generic accent-border panel flagged by the detector.
- Empty task results lack a direct next action.

## Questions to Consider

- Is this fundamentally a project workspace with global Attention, or a collection of global registers?
- Should the app open to Projects or to the work most likely to be forgotten?
- What is the smallest task or file capture that can be completed in ten seconds?
- Which operation deserves the strongest reassurance, and why is it not Move?
- Are Notes, Contacts, and Activity actually one user job?
